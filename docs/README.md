# alpha-signal-evaluation マニュアル

alpha-signal-evaluation は、株式のアルファシグナル（銘柄ごとのスコア）がどれだけ将来のリターンを予測できているかを評価するモジュールです。シグナルとリターンのデータを `config.yaml` で指定すると、IC、分位ポートフォリオ、業種別の分析などの評価指標（metric）を計算し、表として出力します。コマンドは `alpha-eval` です。

このマニュアルは、モジュールを使う方、metric を追加する方、設計の考え方を確認したい方に向けて書いています。コードを読んでいなくても読めます。

## 5分で動かす

リポジトリのルートで実行します。合成データ（値はすべて乱数）で一通りの評価が動きます。

```sh
uv sync                                                        # 依存パッケージを入れる
uv run python examples/example1/make_sample_data.py            # サンプルデータを作る（input/ が既にあれば不要）
uv run alpha-eval validate examples/example1/config.yaml   # 計算せずに設定を検証する
uv run alpha-eval run examples/example1/config.yaml        # 評価して examples/example1/output に書き出す
```

`examples/example1/output/` に、metric ごとのディレクトリ（`ic/`、`quantile/` など）と、全体の要約 `summary.csv`、実行の記録 `run_info.json` ができます。出力の見方は [02 の 6 章](02_features.md#6-出力) を参照してください。

## このモジュールの考え方（要約）

詳しくは [01 設計思想の 2 章](01_design.md#2-4つの原則) にあります。要点は次の4つです。

1. **時点合わせは1か所で行う。** シグナルとリターンの日付の対応は、データを準備する段階で1回だけ決めます。metric はそれを使うだけで、自分ではずらしません。先読みと、指標ごとに対応がずれる事故を防ぐためです。
2. **欠損は欠損のまま扱う。** リターンのない銘柄を 0 で埋めません。
3. **設定の誤りは計算の前にすべて見つける。** 誤りは最初の1つで止めず、一覧で報告します。
4. **認証情報や接続先はコードにも設定ファイルにも書かない。** 環境変数から読みます。

そのうえで最も重視しているのは拡張性です。新しい metric は Python ファイルを1つ置くだけで追加でき、設定・並列実行・ファイル出力・テストは自動で付いてきます。
